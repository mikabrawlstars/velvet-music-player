1. Controller and scope

The controller for the processing described here in connection with Velvet: Music Player, the Velvet account and sync service and this project website is:

Mika Spangenberg
privacy.velvetmusic@gmail.com

This policy applies to the Windows desktop player, whether you got it from the Microsoft Store or as an installer file. It also applies to the Velvet server that signed-in accounts sync with, and to this public information website. It distinguishes between data processed only on your device, data on the Velvet server and connections to third parties that you trigger.

Without signing in ("guest mode"), your library stays exclusively on your device. The developer has no remote access to data on your computer.

2. Data on your device

Depending on the features you use, the following data is stored in the app's local user profile and in the bundled local background service. Without signing in, it is not transferred to the Velvet server. What is synced when you sign in is described in section 3.

Library and settings
Favourites, your own and smart playlists, track assignments, queue, playback position and settings such as language, appearance, preferred provider and audio, lyrics and content safety options. Tracks get their own Velvet identity; their sources can be local files, Spotify or TIDAL.
Listening behaviour, stats and Replay
Tracks played, times, actually measured listening time, qualified plays, play counts and recently played tracks. Velvet uses them to calculate personal statistics, yearly summaries and recommendations. Preferences such as "More like this", "Less like this" or blocked songs and artists are also taken into account.
Search history
Your most recent search terms and search times. Search queries may also reach the catalogue services named in section 5 for the respective search.
Local music and your own TTML lyrics
Selected files and music folders, file paths, tags, covers, technical audio information and information for detecting file changes and duplicates. Your own TTML files are read and assigned for lyrics display. Music files, cover files, file paths and TTML content are never uploaded automatically – neither to music providers nor to Spicy Lyrics or the Velvet server.
Sign-in and provider connections
Your Velvet account session and, if used, Spotify access tokens are stored protected by Windows data encryption (DPAPI).
Diagnostics and recovery
Local start-up and error diagnostics, limited technical request data such as route, status and duration, and recovery data for the current track, queue and playback position. This is not sent automatically to any external analytics service.

On the first sign-in, Velvet can take over existing local library data into your account and keep a local migration copy as a safeguard. Another account on the same device does not receive this data. After signing out, Velvet shows a separate guest library again.

3. Velvet account and cloud sync

A Velvet account is optional. You need it to sync your library between devices, to hand playback over to another device (Continuity) and to use the online catalogues via the Velvet server.

You may create a Velvet account from the age of 16. Younger users need their parents' consent. Anyone can use Velvet without an account.

What is stored on the Velvet server

Account and sign-in
Account ID, username, display name, optional profile picture (PNG, JPEG or WebP up to 250 KB), account role and creation time. For password sign-in, a salted password hash – never the password itself. For each session, a hash of the session token with its expiry time. Registering with a username does not require an email address. There are no public profiles, no user search and no social features.
Google sign-in (optional)
If you use "Sign in with Google" or link Google to your account: your Google user ID, your email address as verified by Google and the time of linking. For a newly created account, your Google name is used as display name. No Google profile picture is loaded. For the duration of a sign-in attempt (at most five minutes), the server also stores technical check values that prevent misuse and replays. Details of the process are in section 5.
Library, settings and listening behaviour
The library data listed in section 2: track metadata and provider IDs, favourites, playlists, queue, listening history with listening time and plays, play counts, recommendation and content safety preferences and general settings. Local file paths and music, cover and TTML files are excluded. Device-specific settings such as the audio output device stay local.
Search history
Your account's most recent search terms (at most 30) with their times.
Continuity / handoff
A device ID, device name, platform and last activity of your signed-in devices, and the current playback session with track, position, play/pause, queue, shuffle, repeat and timestamps. The initial device name may match your computer's name.
Developer features
Only for accounts with developer rights: submitted lyrics versions and a log of editorial changes.

Server, location and data processing

The Velvet server runs on Oracle Cloud Infrastructure in the Frankfurt am Main (Germany) region. The database is on this server and cannot be reached directly from the internet. Oracle acts as a processor under Art. 28 GDPR on the basis of its data processing terms. More information: Oracle Services Privacy Policy.

The app connects to the server over HTTPS. The server's address is resolved via the DNS service sslip.io. Only the server name is queried, never account or library data. To show whether the server is reachable, the installed app contacts it about every 30 seconds, even without signing in. No account data is transferred in doing so.

Server logs

The server keeps no HTTP access log. No IP addresses, request contents or headers are stored. To protect against password guessing, the server counts sign-in and registration attempts per IP address (per network block for IPv6) and per username. This count exists only in memory, is discarded after about 15 minutes and is never written to the database or to logs. For operation, the service logs start-up and error messages without request contents. An internal error overview in memory holds at most 300 entries with time, route pattern, status, duration and error category, but no contents, tokens or passwords.

Who has access

Only the controller, as operator, has access to the server data. Accounts with developer rights cannot see other users' private libraries. Data is not sold and not passed on for advertising.

Offline changes are first stored locally and transferred automatically once you are back online. In case of conflicts, Velvet keeps a local recovery copy.

4. Purposes and legal bases

Velvet processes this data to play music, to manage your library and sync it across devices, to secure sign-ins and access rights, to show lyrics and music videos and to restore playback states or hand them over to another device. Listening and preference data serve only your personal statistics and recommendations within Velvet. No advertising or external product analytics platform is included.

Providing the Velvet account, sync, Google sign-in and the other features you use is based on Art. 6(1)(b) GDPR, the agreement for using the app and your account. The following are based on Art. 6(1)(f) GDPR:

  • the reachability check,
  • protection against misuse and overload,
  • database backups and change logs for recovery and traceability,
  • securely providing this website,
  • handling general contact requests.

The legitimate interests are secure, stable and traceable operation and appropriate communication. Where consent is requested for a processing activity, the legal basis is Art. 6(1)(a) GDPR. Such consent can be withdrawn with effect for the future.

Local music can be used without a Velvet account and without connecting a Spotify or TIDAL user account. Account features require a username, display name and a sign-in method; a profile picture is optional. Without the data or external connections needed in each case, the respective online features are not available.

Recommendations analyse your musical preferences. They do not lead to automated decisions with legal or similarly significant effects within the meaning of Art. 22 GDPR.

5. External services and data transferred

Online requests leave your device. The respective recipient receives the content required for the request and, for technical reasons, among other things an IP address, time and connection information. When you are signed in, catalogue, video and lyrics searches go through the Velvet server. The respective provider then sees the server's address instead of yours and receives no Velvet account data. In guest mode, the local background service on your device contacts the providers directly, if it is set up to do so.

Google sign-in

With "Sign in with Google", Velvet opens Google's sign-in page in your default browser. The sign-in itself happens at Google; Velvet never receives your Google password. Google sends a one-time code back to the app. The Velvet server exchanges it at Google for a signed confirmation of your identity. Only the scopes openid, email and profile are requested. Of these, Velvet stores only the details listed in section 3. Google access tokens are not stored. The email address is used only to detect conflicts between accounts. It is not used for advertising or newsletters. Google processes the sign-in under the Google Privacy Policy. You can revoke granted permissions in your Google account.

Spotify

For catalogue searches, search terms or track, artist and album IDs are sent to Spotify; metadata and cover references come back. When you are signed in, the Velvet server makes these requests with the application's credentials, not with your Spotify account.

If you connect Spotify Connect, you sign in to Spotify via OAuth, exclusively on your device. Velvet receives access and, where applicable, refresh tokens. They stay encrypted on your device and are not transferred to the Velvet server. For Connect, available Spotify devices and the playback state are queried, and playback commands, track IDs, target device, position or volume are sent, among other things.

During setup, your Spotify profile is retrieved to check your subscription status. The granted permissions may also give access to private profile information and your Spotify email address. Velvet does not take these details into your Velvet account. Spotify processes the use of its own service under the Spotify Privacy Policy.

TIDAL

The integration uses the TIDAL catalogue with the application's credentials. Search terms, catalogue IDs and a market/country code are transferred; metadata and cover references come back. There is currently no sign-in to a personal TIDAL account and no full TIDAL audio playback. Provider information: TIDAL Privacy Policy.

YouTube / Google

To find a matching music video, the YouTube Data API is queried with artist, song title and duration. For signed-in users the Velvet server does this, in guest mode the local background service. This search may already happen when the song view is shown, before any video is started. Results are cached without any link to your account.

When you open a music video, Velvet loads the official YouTube IFrame player in privacy-enhanced mode via youtube-nocookie.com. This creates direct connections from your device to Google/YouTube. The provider receives, among other things, the video ID, your IP address, technical device and browser data and playback interactions. Depending on use, cookies or similar storage may be involved. Privacy-enhanced mode does not prevent every data transfer. The Google Privacy Policy applies.

Spicy Lyrics

Spicy Lyrics is used only by the local background service on your device, and only if it is set up for it. If no preferred TTML of your own exists, it calls the official Spicy Lyrics Developer API. The Spotify track ID assigned to the song is transmitted; if needed, catalogue metadata is queried first to identify the song. Spicy receives no Velvet credentials, no Velvet account ID and no personal library.

The response may contain synced or static lyrics and details of the source, uploader and maker. Velvet shows these details and any profile links supplied for attribution; clicking a credit link opens the respective external website. The lyrics are stored only temporarily for display. More information: Spicy Lyrics Developer API privacy.

Microsoft Store

If you install Velvet from the Microsoft Store, Microsoft processes data on purchase, download, installation and updates under its own responsibility, according to the Microsoft Privacy Statement. The developer receives no payment data through this. The developer may receive aggregated statistics from Microsoft (such as download numbers) and, depending on your Windows diagnostic settings, crash reports.

Covers, links and international processing

Covers and other provider images are loaded directly from the providers' image servers, for example Spotify or TIDAL. Your IP address is transmitted to the respective provider in doing so. External links are only opened in your browser when you click them. The privacy policy of the respective website then applies.

The Velvet server is located in Germany. The third parties named above and their service providers may also process data outside the European Economic Area, in particular in the USA; Spicy, for example, states US hosting for its Developer API. In their linked privacy information, the providers explain their international transfers, for example on the basis of adequacy decisions or standard contractual clauses.

Velvet does not store passwords for your music providers. Provider tokens are stored protected and separately from the library. They are not synced with playlists or settings.

6. Retention

Velvet account and synced data
Account, profile, synced library, settings, listening history, statistics and Continuity devices are stored for as long as your account exists. They are deleted afterwards (see section 8). You can change or remove individual entries in the app at any time.
Local data
Data on your device – including the guest library, local account copies, migration and recovery copies and backups you created – remains until you change or remove it. Signing out or deleting the account on the server does not remove it automatically.
Search history
At most the 30 most recent search terms are kept. You can clear the history in the app.
Velvet sessions
A session is valid for at most 30 days. It is revoked when you sign out. If the server is unreachable at that moment, the revocation is queued and made later. Expired sessions no longer grant access. Their entries are deleted at the next sign-in of any user and may remain in the database until then.
Google sign-in
Technical check values of a sign-in attempt become invalid after at most five minutes. They are deleted when the attempt completes or, at the latest, at the next Google sign-in attempt. The Google link remains until you remove it in the app or your account is deleted.
Database backups
The database is backed up daily and additionally before server updates. Backups are stored on the server and, as a second copy, in Oracle Cloud Infrastructure's storage service in Frankfurt, and are kept for at most 30 days. Data of a deleted account may remain in a backup until this period ends. If a backup has to be restored, deleted accounts are removed again.
Spotify tokens
Access tokens are valid for the period set by the provider. A refresh token allows renewal until the connection is removed or the permission revoked. When you disconnect Spotify in Velvet, the local token storage is removed.
Spicy Lyrics cache
Lyrics and related details stay only in the memory of the local background service, for at most seven days, shorter if evicted or on restart. This is below the maximum of 30 days permitted by Spicy.
YouTube search results
A found video is cached for up to seven days, a result without a match for up to one day, without any link to an account. Expired entries are removed at start-up and hourly afterwards.
Logs
The count of sign-in attempts per IP address and username exists only in memory and is discarded after about 15 minutes (about one minute for Google sign-in). The internal error overview holds at most 300 entries in memory and is lost on restart. Start-up and error messages of the service contain no personal request contents. Change logs of developer accounts remain as long as the edited data exists.
Contact and external services
Contact requests are kept as long as they are needed for handling and necessary traceability. They are then deleted unless a statutory retention obligation or a specific legal defence prevents this. For data held by Google, Spotify, TIDAL, Spicy, Microsoft, Oracle and GitHub, their own retention rules also apply.

7. Security

Velvet passwords are stored with a random salt using the scrypt hashing method, never in plain text. Sign-in attempts are limited. The server stores only a hash of the session token. On your device, account sessions and Spotify tokens are encrypted with the operating system's protection; there is no unencrypted fallback storage. Session tokens are only ever sent to the Velvet server that issued them.

The connection between the app and the Velvet server is encrypted with TLS (HTTPS). The server service runs with restricted privileges. The database is reachable only locally on the server. Credentials for Google, Spotify, TIDAL and YouTube are kept only on the server or in your local configuration and are not included in the app. Account and developer permissions are checked on the server for every request.

Data on your device, such as the local library and backups you created, is not encrypted automatically. Protecting your Windows account, your drive and your backup copies therefore remains important.

8. Your rights and deleting data

Where the legal requirements are met, you have in particular the following rights: access to and a copy of your data, rectification, erasure, restriction of processing and data portability. You can object to processing based on legitimate interests on grounds relating to your particular situation. You can withdraw consent with effect for the future.

You can also lodge a complaint with a data protection supervisory authority, in particular in the member state of your habitual residence, place of work or the place of the alleged infringement. A list of EU authorities is provided by the European Data Protection Board; German authorities are listed in the overview of the Hessian Commissioner for Data Protection (German).

Directly in Velvet

In Velvet you can yourself:

  • change your display name and profile picture,
  • remove favourites and edit or delete playlists,
  • clear your search history,
  • remove the Google link, as long as a password sign-in remains,
  • disconnect provider connections.

Changes are synced with the server. The backup feature saves local library data, settings and your own TTML files.

A copy of your data

On request you receive a copy of all server data of your account as a machine-readable JSON file. Requests go to the email address below, with the same confirmation as for deletion by email. You can save the data on your device yourself at any time with Velvet's backup feature.

Deleting your Velvet account

From Velvet 2.14.10 you can delete your account yourself: Settings → General → Velvet Account → Delete account. To confirm, you enter your password and your username. If your account uses Google sign-in only, a Google sign-in from the last ten minutes is required instead. Signing out alone deletes nothing; it only ends the sign-in on that device.

On the Velvet server, the account and profile, all sessions, the Google link, the synced library with settings, listening history and statistics, the search history and Continuity devices and session are deleted. On the device where you delete, Velvet also removes the local copy of this account. Data disappears from database backups after 30 days at the latest (see section 6).

Developer and owner accounts, and accounts you can no longer access, are deleted by me on request to privacy.velvetmusic@gmail.com. Please state your Velvet username. Because no email address is stored for a username registration, I may ask you to confirm by temporarily entering a code I give you as your display name in Velvet. Never send your password for this. For developer accounts, submitted lyrics versions and log entries are deleted or kept without reference to you.

On other devices, a local copy remains until you remove it there; I cannot delete it remotely. The guest library, migration and recovery copies and your own backups are in the Velvet data folder of your Windows user profile. Uninstalling does not necessarily remove them. You decide yourself about your original music and TTML files.

The same email address applies for all other rights. I generally answer such requests within one month; legally permitted extensions will be communicated. Please do not send passwords, tokens or database copies. Reasonable identity verification may be required.

Deleting in Velvet does not delete data in your Spotify, Google or other provider accounts. You manage data stored there and app permissions you granted with the respective provider.

9. Visiting this GitHub Pages website

This public documentation is provided via GitHub Pages. It contains no tracking, no analytics scripts, no external fonts and no embedded players. The site itself sets no cookies and stores no data in browser storage.

When the page is accessed, GitHub processes technical connection data and in particular stores IP addresses for security purposes, even without a GitHub login. Providing and securing this information page serves the legitimate interest in reachable project documentation. Further details on recipients, international processing, retention criteria and rights are in the GitHub General Privacy Statement. GitHub also describes the IP logging in its Pages documentation.

This website is separate from the Velvet server. Visiting it transfers no library and no Velvet sign-in session to GitHub.

10. Privacy contact

For questions or concerns about the processing of your data, you can reach Mika Spangenberg at privacy.velvetmusic@gmail.com. Requests in English or German are welcome.

If you send an email, your sender address, the content and any further details you choose to provide are used to handle it. The mailbox is hosted by Gmail. Google processes the message and technical delivery data as part of the email service; the Google Privacy Policy applies in addition. Contacting me does not require a Velvet account.
